# Apothecary Oils — Personal Oils Database — Design Spec

- **Date:** 2026-08-30
- **Repo:** git@github.com:matus1331/apothecary-oils.git
- **Status:** Approved design, ready for implementation planning

## 1. Purpose & Scope

A single-user personal database of essential oils, carrier oils and hydrosols.
No authentication. The user views a grouped, sortable table of oils and can
add / edit / delete entries through a form. The app warns in-app about oils
approaching expiry. It ships as an installable PWA that works well on mobile
and can read previously loaded data offline.

### In scope

- Grouped table (3 fixed sections by product type) with per-section column sorting.
- Add / edit / delete oil (full CRUD) via a drawer/sheet form.
- Manufacturer field that remembers previously entered manufacturers and offers
  them in a combobox.
- In-app expiry awareness: banner + row highlighting for oils expiring within
  90 days, and for already-expired oils.
- "Low stock / running out" boolean indicator per oil.
- Free-text note per oil.
- Light/dark theme, apothecary visual style.
- Installable PWA: cached app shell + offline reading of last-loaded data.
- Deployment on Vercel, source on GitHub, data in Turso (libSQL).

### Out of scope (YAGNI)

- Any authentication / accounts / multi-user.
- Push notifications, email reminders, backend cron jobs.
- Full offline write support / sync queue / conflict resolution. Offline is
  read-only; mutations require connectivity.
- Managing (renaming/deleting) manufacturers from the UI.
- Quantity tracking beyond the single "low stock" boolean; multiple bottles per oil.
- Images/attachments, tags, categories beyond product type.
- Routing beyond a single screen (a modal-as-route deep link to the form is optional).

## 2. Architecture

**Chosen approach:** Vite + React (TypeScript) SPA + a thin Hono API running as
Vercel Functions + Drizzle ORM + Turso (libSQL).

Rationale: the Turso auth token is a secret, so the SPA cannot talk to Turso
directly — an API layer is required regardless. Hono (~14 kB) plus Drizzle keep
that layer thin and fully typed without adopting a meta-framework. This keeps
the "plain Vite" character the user asked for.

```
Browser (React SPA, React Query cache)
   │  fetch  /api/oils, /api/manufacturers
   ▼
Vercel Function  (Hono app, Zod validation)
   │  Drizzle ORM
   ▼
Turso  (libSQL / SQLite)
```

- **Client → server:** typed `fetch` wrapper + React Query hooks. React Query's
  cache, persisted via the service worker's NetworkFirst strategy, is the basis
  for offline reading.
- **Validation:** Zod schemas in `src/shared/schema.ts` are imported by both the
  client (form validation) and the Hono API (request validation), so the
  contract is defined once.
- **Server shape:** a single Hono app exported as the default handler from
  `api/index.ts` (catch-all `api/[[...route]].ts` if Vercel routing needs it),
  with routes `/api/oils` (GET list, POST create) and `/api/oils/:id`
  (PUT update, DELETE) plus `/api/manufacturers` (GET list; manufacturers are
  created as a side effect of creating/updating an oil, not via their own POST).
- **No SSR.** The loading screen (section 7) covers first paint.

## 3. Data Model

Turso / libSQL, schema defined with Drizzle in `db/schema.ts`, migrations
generated by `drizzle-kit` and committed to the repo.

### `manufacturers`

| column       | type              | notes                                        |
|--------------|-------------------|----------------------------------------------|
| `id`         | integer, PK, autoincrement |                                     |
| `name`       | text, NOT NULL    | unique case-insensitively (unique index on `lower(name)`) |
| `created_at` | integer (epoch ms), NOT NULL, default now |                        |

### `oils`

| column            | type                       | notes                                                                 |
|-------------------|----------------------------|----------------------------------------------------------------------|
| `id`              | integer, PK, autoincrement |                                                                    |
| `product_type`    | text, NOT NULL             | enum: `essential` \| `carrier` \| `hydrosol` (CHECK constraint)     |
| `name`            | text, NOT NULL             | max 120 chars (enforced in Zod)                                     |
| `latin_name`      | text, nullable             | max 120 chars                                                       |
| `manufacturer_id` | integer, nullable, FK → `manufacturers.id` | `ON DELETE SET NULL`                                |
| `expiry_date`     | text, nullable             | ISO `YYYY-MM-DD`                                                    |
| `low_stock`       | integer, NOT NULL, default 0 | 0/1 boolean — "running out" indicator                             |
| `note`            | text, nullable             | free text, max ~2000 chars                                          |
| `created_at`      | integer (epoch ms), NOT NULL, default now |                                                     |
| `updated_at`      | integer (epoch ms), NOT NULL, default now | bumped on every update                               |

### Product type mapping (UI labels, Slovak)

| enum value  | UI label        |
|-------------|-----------------|
| `essential` | Eterický olej   |
| `carrier`   | Rastlinný olej  |
| `hydrosol`  | Hydrolát        |

Fixed section order in the table: `essential` → `carrier` → `hydrosol`.

### Behaviour

- Creating an oil with a manufacturer name that does not yet exist:
  `INSERT OR IGNORE INTO manufacturers(name)` (case-insensitive), then resolve
  `manufacturer_id` and store it on the oil. From then on the manufacturer
  appears in the combobox list.
- Manufacturers are never deleted from the UI. They accumulate only when
  actually used.
- Expiry status is **not** computed in the database. The frontend derives it
  from `expiry_date` vs. today.

## 4. Expiry Logic

Pure function `expiryStatus(expiryDate: string | null, today: Date): 'expired' | 'expiring' | 'ok' | 'none'`:

- `none` — no `expiry_date` set.
- `expired` — `expiry_date` is strictly before today (date-only comparison, local time).
- `expiring` — `expiry_date` is today or within the next 90 days (inclusive of day 90).
- `ok` — more than 90 days away.

Also `daysUntil(expiryDate, today)` for display ("o 34 dní" / "pred 5 dňami").

- **Banner** appears above the table only when at least one oil is `expiring` or
  `expired`. Copy: `⚠ {n} olej/oleje/olejov expiruje do 90 dní` (with a separate
  count for already expired if any). A "zobraziť" action sorts/scrolls to the
  affected rows (e.g. applies expiry-date ascending sort).
- **Row highlight:** `expiring` → amber background (`--warn-bg`) + amber dot near
  the date; `expired` → brick-red background (`--danger-bg`) + "expirované" label.
  Highlighting is purely visual and never blocks interaction.

## 5. Screens & UX

Single screen. No router required (optional modal-as-route for a shareable link
to the add form).

### Layout (desktop)

```
┌─────────────────────────────────────────────┐
│  Oleje              [＋ Pridať olej]         │  sticky header (+ theme toggle, install btn, offline badge)
├─────────────────────────────────────────────┤
│  ⚠  3 oleje expirujú do 90 dní   [zobraziť] │  banner — only when relevant
├─────────────────────────────────────────────┤
│  ETERICKÉ OLEJE  (12)                        │  section = product type
│  Názov ▲ │ Latinský │ Výrobca │ Exp. │ ⬤    │  sortable column headers
│  Levanduľa  Lavandula…  Nobilis  2026-11  ● │  ● = low stock
│  Mäta       Mentha…     doTERRA  2026-03 ⚠  │  amber row = expiring
│  RASTLINNÉ OLEJE (5) …                       │
│  HYDROLÁTY (3) …                             │
└─────────────────────────────────────────────┘
```

### Table

- Three fixed sections in the order above. A section with 0 rows is hidden
  (or shows a muted "zatiaľ žiadne" line — implementer's choice, hidden preferred).
- Sortable columns within each section: Názov, Latinský názov, Výrobca,
  Dátum expirácie, low-stock. Header click cycles ▲ → ▼ → off (off = default
  sort by Názov ▲). Sorting is applied independently but identically across all
  sections (one global sort state).
- Sort state persisted in the URL query: `?sort=expiry_date&dir=asc`. Survives
  reload and is shareable.
- Null values sort last regardless of direction (empty latin name, no expiry date).
- Row click opens the detail/edit panel: a right-side **drawer** on desktop, a
  full-screen **sheet** on mobile.

### Form (Add / Edit — same component)

| field           | control                                                                 |
|-----------------|------------------------------------------------------------------------|
| Typ produktu    | segmented control, 3 options, required                                 |
| Názov           | text, required, ≤ 120                                                  |
| Latinský názov  | text, optional, italic placeholder, ≤ 120                             |
| Výrobca         | combobox — type to filter existing; if no match → "➕ Vytvoriť «X»"     |
| Dátum expirácie | native `type=date` input + quick chips "+1 rok" / "+2 roky"           |
| Dochádza        | toggle switch (maps to `low_stock`)                                   |
| Poznámka        | auto-growing textarea, ≤ ~2000                                        |

- Validation via the shared Zod schema. Required: Typ + Názov. `expiry_date`, if
  present, must be a valid ISO date.
- Actions: **Uložiť** / **Zrušiť**. In edit mode also **Zmazať** (danger style)
  behind a confirm dialog: "Naozaj zmazať «{name}»?".
- Mutations use React Query optimistic updates: the table reflects the change
  immediately; on error, roll back and show an error toast.
- Manufacturer combobox: filtering is client-side over the fetched list;
  choosing "Vytvoriť «X»" just sets the free-text value — the manufacturer row
  is actually created server-side when the oil is saved.

### Empty state

Illustrated small bottle + "Zatiaľ žiadne oleje" + primary button "Pridať prvý olej".

### Mobile (< 640 px)

- Table → **cards**: name + italic latin name, a line "Výrobca • Exp. dátum",
  status / low-stock icons on the right. Section headings remain.
- Sorting via a "Zoradiť podľa ▾" dropdown instead of column-header clicks.
- "Pridať" as a FAB bottom-right.
- Form is a bottom sheet, full height.
- `viewport-fit=cover`; respect safe-area insets for the FAB and sticky header.

## 6. Visual Design System — "modern apothecary"

Detailed execution is delegated to the `frontend-design` skill during
implementation. Direction:

### Colour tokens (CSS variables mapped into Tailwind `@theme`)

| token           | light                       | role                                  |
|-----------------|-----------------------------|---------------------------------------|
| `--bg`          | `#F7F4EE` warm cream        | page surface                          |
| `--surface`     | `#FFFFFF` / `#FCFAF6`       | cards, drawer                         |
| `--ink`         | `#2A2724` warm near-black   | primary text                          |
| `--muted`       | `#6B655C`                   | secondary text, latin names           |
| `--line`        | `#E4DDD0`                   | borders, dividers                     |
| `--accent`      | `#3B5D4E` deep green        | buttons, active sort, links           |
| `--accent-weak` | `#E8EFEA`                   | hover, active section                 |
| `--warn`        | `#B0791F` amber             | "expiring"                            |
| `--warn-bg`     | `#FBF1DF`                   | expiring row background               |
| `--danger`      | `#9A3B2E` brick             | "expired", delete                     |
| `--danger-bg`   | `#F6E4E0`                   | expired row background                |

Dark theme: page `#1E1C19`, surface `#262320`, accent lightened to `#7FB39B`,
warn/danger muted, tokens redefined under the dark selector. Theme toggle in the
header, stored in `localStorage`, default = system (`prefers-color-scheme`).

### Typography

- Headings / "Oleje" / section headings: **Fraunces** (serif, apothecary
  character), self-hosted via `@fontsource/fraunces`, fallback `Georgia, serif`.
- Data / UI / form: **Inter**, self-hosted, fallback `system-ui`.
- Latin names always *italic*, colour `--muted`.
- Section headings: serif, uppercase, small, `letter-spacing: 0.08em`.

### Components

- 1px lines over heavy shadows; drawers/cards get only a very soft shadow.
- Radius: 10px cards, 8px inputs, 999px chips.
- Segmented control for product type with serif labels.
- Icons: **Lucide** (thin, neutral). Optionally three subtle plant pictograms
  for the product types (leaf / seed / droplet).
- Respect `prefers-reduced-motion` everywhere (disable non-essential motion).

### Animation (Framer Motion + CSS keyframes — stands in for 21st.dev pieces)

- **Loading screen:** full-viewport, cream background, an animated oil droplet
  falling into a bottle / ripple on the surface (inline SVG + `motion` path),
  caption "Pripravujem tvoju zbierku…". Held a minimum ~400ms to avoid a flash,
  then fades out.
- **Skeleton** table/card rows during fetch (shimmer keyframe).
- Drawer / sheet: spring slide-in.
- Expiry banner: slide-down + fade on appear.
- Table rows: Framer `layout` animation when sort changes (rows glide to new
  positions); 15ms stagger on first load.
- Toasts: slide + fade, auto-dismiss 4s.
- Buttons: `scale: 0.97` on press.

Note: `21st.dev` / Magic MCP is not connected in this environment. If it is
added later, individual components can be pulled from it as references and
rewritten to match this system.

## 7. PWA

- **`vite-plugin-pwa`** (Workbox), `registerType: 'autoUpdate'`.
- **Manifest:** name "Oleje", short_name "Oleje", `display: standalone`,
  `theme_color #3B5D4E`, `background_color #F7F4EE`, icons 192 / 512 + maskable,
  `orientation: portrait`.
- **Caching:**
  - App shell (JS/CSS/HTML/fonts) → precache — the app launches offline.
  - `GET /api/oils`, `GET /api/manufacturers` → NetworkFirst with cache
    fallback and a ~3s network timeout — offline reading of last-loaded data.
  - `POST` / `PUT` / `DELETE` → not intercepted by the SW. When offline, React
    Query surfaces the error and a toast says
    "Bez pripojenia — zmena sa neuložila".
- Fonts self-hosted via `@fontsource/*` (never a CDN) — required for offline and
  faster.
- **Install prompt:** a discreet "Nainštalovať" button in the header shown when
  `beforeinstallprompt` fires. On iOS (no prompt support) a quiet hint in an
  "O aplikácii" section instead.
- `apple-touch-icon`, `viewport-fit=cover`, `theme-color` meta for the iOS status bar.
- **Offline indicator:** small "offline" badge in the header driven by
  `navigator.onLine` + `online`/`offline` event listeners.

## 8. Deployment

- **GitHub:** `git@github.com:matus1331/apothecary-oils.git` (already created).
  `main` branch, initial commit contains this spec.
- **Vercel:** import the repo, "Vite" preset. `/api/*` functions auto-detected
  (Hono default export from `api/index.ts`, or `api/[[...route]].ts` catch-all).
- **Env vars** (Vercel dashboard + local `.env`, git-ignored):
  - `TURSO_DATABASE_URL`
  - `TURSO_AUTH_TOKEN`
  - `.env.example` committed with placeholder keys.
- **Turso setup:** `turso db create oils`; `turso db tokens create oils`.
  Migrations: `drizzle-kit generate` → SQL committed; applied manually via
  `npm run db:migrate` (dataset is tiny; no automated migrate step needed).
- **No authorization** per requirements — the app and `/api` are public.
  Soft mitigations only: in-memory rate limit middleware on mutations, and
  `robots: noindex`. (A single shared password could later be added as one Hono
  middleware; not in scope now.)
- **Node version** pinned via `"engines"` in `package.json` and `.nvmrc`.
- Preview deployments on every PR.

## 9. Testing

- **Vitest + Testing Library** (unit / component):
  - Zod schema boundaries: required fields, length limits, date format.
  - `expiryStatus(date, today)` — case table: today, +89d, +90d, +91d, past, null.
  - `daysUntil` formatting.
  - Manufacturer combobox: filtering, "create new", selecting existing.
  - Section sort: stability, ▲/▼/off cycling, nulls-last.
  - Table render: correct section placement, highlighted rows, hidden empty sections.
- **API tests** (Vitest) against the Hono app with in-memory libSQL (`:memory:`):
  CRUD happy paths, `INSERT OR IGNORE` manufacturer, `ON DELETE SET NULL`,
  validation rejections.
- **One e2e smoke** (Playwright, optional): add oil → appears in correct section
  → edit → delete.
- **CI:** GitHub Actions — `lint + typecheck + vitest` on push / PR.
- **TDD** (per `test-driven-development` skill): pure functions (expiry, sort,
  validation) and the API layer are written test-first.
